1. Set up MyEvent

  1. Open MyEvent.app. It is a regular Dock application; its window contains settings only.
  2. In General, choose your interface language and global shortcut. Click the shortcut button and press a combination with Command, Option or Control and another key. Press Escape to cancel. The initial default is ⌘⇧M; an existing shortcut is preserved when upgrading.
  3. In Permissions, allow Accessibility in System Settings → Privacy & Security → Accessibility. This lets MyEvent read selected text in other applications.
  4. In Accounts, allow full calendar access and check one or more destination calendars. Calendars are grouped by account. Read-only calendars cannot be selected.
  5. Choose the default duration and time in General. There are no sound settings; MyEvent creates events silently.

Multiple destinations: every selected calendar receives a separate copy. Check your selection to avoid unwanted duplicates.

Only accounts synced with the macOS Calendar app are available. An account used only inside Outlook may not appear. Use Manage accounts… to configure it in macOS, then click Refresh.

2. Create an event

  1. Select text in another app, such as a browser, Notes or an email.
  2. Press your configured shortcut and release the keys. The Dock logo immediately pulses with a blue ring to acknowledge receipt, then continues while the request is processed. The animation lasts at least 1.2 seconds, including when a request fails, and does not mean the event was saved. It restores the normal icon after processing and does not bring the source app out of focus.
  3. MyEvent reads the text and immediately saves the event to every chosen calendar. There is no preview or extra confirmation.

Example: Project meeting tomorrow from 14:30 to 15:45. Relative-day and weekday expressions are recognized in the supported languages; for example Réunion demain de 14h30 à 15h45. Date recognition otherwise depends on macOS and the text format.

The first non-empty translated line becomes the event title (up to 160 characters), with common subject/title labels removed. Notes include localized start and end dates, an explicitly labeled location when present, detected email addresses as participant references, web links and the full translated selection under Details. Dates are parsed from the original selection before translation. No untranslated original is appended. Names and URLs may remain unchanged. Email references are not meeting invitations. The first web link is also saved in the event URL field. One selection creates one event per chosen calendar; recurring schedules and lists of separate events are not automatically expanded.

After a successful save, a small native popup shows the event title, start/end times, location when present, destination calendars and detailed notes. Below the divider, the popup omits the generated Start/End preamble and the Details heading, because dates are already shown above. The underlying event notes retain their full structure. The popup has only a Close button; there are no buttons to open Outlook or Apple Calendar. General contains no calendar-opening application selector. Calendar destination selection remains in Accounts and controls where events are created. MyEvent no longer sends automation commands to calendar apps or requests Automation permission. The panel stays open until you click Close or its window close button. There is no automatic dismissal timer; creating another event does not close earlier receipts. Quitting MyEvent closes all its windows. It does not activate MyEvent or reopen, restore or unhide Settings. Errors are also shown in a separate popup without bringing Settings forward. There is no sound playback.

To edit or delete a created event, use the macOS Calendar app. Pressing the shortcut again creates another event.

3. Choose your interface language

Open General → Language. English is the initial default, regardless of your Mac's language. Changes apply immediately and are saved for the next launch.

Available languages: English, Mandarin Chinese (Simplified), Hindi, Spanish, Arabic, French, Portuguese, German and Italian. Arabic uses a right-to-left layout.

Nine languages are available. German and Italian replace Bengali, Indonesian and Urdu in this release.

The chosen language controls both the interface and the text of new calendar events. MyEvent translates the title and detailed notes locally when the selected text is in another language. Calendar account names are not translated. This help guide remains in English.

Local translation languages

MyEvent detects the source language automatically. There is no translation-source list or preparation button in Settings. If language models are missing, install the source and target languages in System Settings → General → Language & Region → Translation Languages, then try the shortcut again.

Unattended translation requires macOS 26 or later and installed source/target models. Pair availability depends on macOS; a listed interface language is not a guarantee of translation support. If translation is unsupported, assets are missing, or the source language cannot be identified, no event is created and Settings explains the problem. On older macOS versions, text already in the chosen language can still be saved, but cross-language event creation is blocked.

Translation is based on the detected dominant source language. Mixed-language selections and very short text may be interpreted incorrectly. Prefer a selection written mainly in one language; use Calendar to correct any translation.

Troubleshooting

The shortcut does nothing

Make sure MyEvent is running in the Dock. The red close button on Settings quits MyEvent and disables the shortcut, as does ⌘Q. The yellow minimize button keeps MyEvent and the shortcut running. Closing the Help window only closes Help. Check Accessibility permission. Try a different shortcut if the current app or macOS intercepts it. A brief cooldown prevents repeated keypresses from creating several copies.

No selected text is accessible

Select actual text in the source application. Release the shortcut keys. MyEvent first tries Accessibility, then Copy. Protected fields or some applications may block both methods; try a source application that exposes text selection.

My account or calendar is missing

Add the account to macOS Calendar and enable calendar syncing. Allow full calendar access for MyEvent, return to Accounts and click Refresh. Read-only and subscribed calendars cannot be used as writable destinations.

A selected destination is unavailable

MyEvent blocks creation rather than silently switching destinations. Restore the calendar or remove unavailable destinations in Accounts, then select the calendars you want.

Permissions stopped working after an update

Earlier builds used ad-hoc signatures, tied to each binary hash. Current builds use the Mac's Apple Development signing identity (or MYEVENT_SIGNING_IDENTITY) to preserve a certificate-based identity across rebuilds. Changing from the old signature requires one new authorization. In System Settings → Privacy & Security, check Calendars and Accessibility for MyEvent. If MyEvent is already enabled but Permissions says Not allowed, remove the old Accessibility entry using the minus button, add the current app using the plus button, enable it, then quit and reopen MyEvent. The Permissions tab shows the exact running app path. It rechecks the system status every second while active, when opened, and when the app becomes active. Refresh checks it manually. The live check only reads permission status; it does not repeatedly request access or reload calendar contents. The app never treats a checked-looking stale entry as permission.

An event has the wrong date

Open Calendar to correct it. Include an explicit date and time in the selection next time. Text without a recognized date creates an event tomorrow using the configured defaults.

Events appear more than once

Each selected calendar receives one copy. Pressing the shortcut again also creates another event. Review your destinations in Accounts and remove unwanted copies in Calendar.

Privacy and availability

Selected text is processed locally. MyEvent does not send it to an external AI service, add its own analytics or require an API key. Apple Translation processes text on-device; Apple may collect language-pair and API usage metrics, but not the source or translated content, as described in Apple's TranslationSession documentation. Event text and notes are saved to your selected calendars; those calendars may sync through their account providers.

If MyEvent needs to use Copy, it preserves the available clipboard formats and restores them after reading, unless it detects a concurrent clipboard change. Settings and the chosen language are stored locally. The bottom of Settings displays the version, build number and build date. A build increments its number every time, and a code change increments the patch version. A build refuses code changes unless this English guide has also been updated.

The ? button and Help menu open one reusable native macOS help window, not your browser. Reopening Help returns to this guide. Links remain inside that window. MyEvent has one settings window only; no empty system Settings scene is created. The app bundle declares its ICNS icon explicitly. Builds use Apple’s native iconutil encoder for every Finder/Dock icon size, including small list icons, and refresh Launch Services registration. This guide is bundled with the app and opens in a dedicated MyEvent macOS window without an internet connection. Links to external references require internet access. No online-hosted guide is configured: Sites publication is not enabled for this workspace. The guide is regenerated and bundled with every build; hosting remains a separate blocked step.

Requires macOS 14 or later. This build runs on the architecture of the Mac used to compile it. Distribution to other Macs requires appropriate signing and notarization.
