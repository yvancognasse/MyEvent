1. Set up MyEvent

Settings opens at a compact 512 × 471 points, including its title bar. This is also its minimum size. You can enlarge it; longer content in Accounts or Permissions scrolls. Hiding and showing the window retains its current size during the session; restarting restores the compact default.

  1. Open MyEvent.app. It is a regular Dock application; its window contains settings only.
  2. In General, choose your interface language and global shortcut. Click the shortcut button and press a combination with Command, Option or Control and another key. Press Escape to cancel. The initial default is ⌘⇧M; an existing shortcut is preserved when upgrading.
  3. In Permissions, allow Accessibility in System Settings → Privacy & Security → Accessibility. This lets MyEvent read selected text in other applications.
  4. In Accounts, allow full calendar access and check one or more destination calendars. Calendars are grouped by account. Read-only calendars cannot be selected.
  5. There are no default-duration, default-time or sound controls. Review dates and times in the draft before confirming.

Multiple destinations: every selected calendar receives a separate copy. Check your selection to avoid unwanted duplicates.

Only accounts synced with the macOS Calendar app are available. An account used only inside Outlook may not appear. Use Manage accounts… to configure it in macOS, then click Refresh.

2. Review and create an event

  1. Select text in another app and press your configured shortcut, then release the keys.
  2. The Dock logo pulses to acknowledge receipt while MyEvent reads the selection, parses the original dates and translates the text if needed. The animation does not mean an event was saved.
  3. A separate native Review event popup opens. No calendar event has been written yet. Click a field to edit the title, start and end dates/times, location, web link or notes. Check the displayed destination calendars.
  4. Click Create event to save the reviewed values. A title is required, the end must be later than the start, and an optional link must use http or https. Validation errors prevent creation. If saving fails, the popup keeps your edits and shows an error so you can retry.
  5. After saving, the same popup displays Event created. The editor is replaced by a read-only summary and the confirmation button disappears. It stays open until you click Close or its window close button.

Clicking Cancel or closing an unconfirmed popup discards that draft without writing any event. Closing a popup does not quit MyEvent. Settings stays hidden or minimized if it was hidden or minimized; editing the popup does not reopen Settings. There is no automatic dismissal or sound playback.

The first non-empty translated line supplies the initial title (up to 160 characters). Notes initially include a detected labeled location, email references, web links and the translated selection. The editor omits the generated Start/End preamble and Details heading; the notes you review are saved exactly as edited, without regenerating old dates. Dates written inside the selected source text remain part of the notes unless you edit them. The first web link supplies the editable Link field. Email references never create invitations. Your manual edits are saved as entered and are not automatically retranslated.

The destination calendars shown when the draft is prepared are retained for that draft. Changing Accounts affects new drafts, not an already open one. Every listed calendar receives one copy only after confirmation. If any destination becomes unavailable or read-only, or permission is revoked, saving is blocked and your edits remain. Cancel and prepare a new draft to use different destinations.

One selection prepares one event per destination; recurring schedules and lists of separate events are not expanded. The popup has no button to open Outlook or Apple Calendar and General has no calendar-opening application selector. To edit or delete an event after confirmation, use your calendar app. Pressing the shortcut again prepares a separate draft.

3. Choose your interface language

Open General → Language. English is the initial default, regardless of your Mac's language. Changes apply immediately and are saved for the next launch.

Available languages: English, Mandarin Chinese (Simplified), Hindi, Spanish, Arabic, French, Portuguese, German and Italian. Arabic uses a right-to-left layout.

Nine languages are available. German and Italian replace Bengali, Indonesian and Urdu in this release.

The chosen language controls both the interface and the text of new calendar events. MyEvent translates the title and detailed notes locally when the selected text is in another language. Calendar account names are not translated. This help guide remains in English.

Local translation languages

MyEvent detects the source language automatically. There is no translation-source list or preparation button in Settings. For cross-language selections, translation runs in the background when the required models and permissions are ready: only the event review popup appears. A temporary translation window opens only if the background attempt cannot complete, so macOS can request permission or offer required language downloads. Keep that window open until translation completes. Cancel or close it to discard the request without creating an event. If a download cannot complete, install the source and target languages in System Settings → General → Language & Region → Translation Languages, then try the shortcut again.

Unattended translation requires macOS 26 or later and supported source/target models (macOS may offer to download them). Pair availability depends on macOS; a listed interface language is not a guarantee of translation support. If translation is unsupported, required models cannot be downloaded, or the source language cannot be identified, no event is created and a separate error popup explains the problem. On older macOS versions, text already in the chosen language can still be saved, but cross-language event creation is blocked.

Translation is based on the detected dominant source language. Mixed-language selections and very short text may be interpreted incorrectly. Prefer a selection written mainly in one language; correct the proposed text in the review popup before confirmation, or use Calendar after saving.

Troubleshooting

The shortcut does nothing

Make sure MyEvent is running in the Dock. The red close button on Settings quits MyEvent and disables the shortcut, as does ⌘Q. The yellow minimize button keeps MyEvent and the shortcut running. Closing the Help window only closes Help. Check Accessibility permission. Try a different shortcut if the current app or macOS intercepts it. A brief cooldown prevents repeated keypresses from opening several drafts. No event is created until you confirm a draft.

No selected text is accessible

Select actual text in the source application. Release the shortcut keys. MyEvent first tries Accessibility, then Copy. Protected fields or some applications may block both methods; try a source application that exposes text selection.

My account or calendar is missing

Add the account to macOS Calendar and enable calendar syncing. Allow full calendar access for MyEvent, return to Accounts and click Refresh. Read-only and subscribed calendars cannot be used as writable destinations.

A selected destination is unavailable

MyEvent blocks creation rather than silently switching destinations. Restore the calendar or remove unavailable destinations in Accounts, then select the calendars you want.

Permissions stopped working after an update

Earlier builds used ad-hoc signatures, tied to each binary hash. Current builds use the Mac's Apple Development signing identity (or MYEVENT_SIGNING_IDENTITY) to preserve a certificate-based identity across rebuilds. Changing from the old signature requires one new authorization. In System Settings → Privacy & Security, check Calendars and Accessibility for MyEvent. If MyEvent is already enabled but Permissions says Not allowed, remove the old Accessibility entry using the minus button, add the current app using the plus button, enable it, then quit and reopen MyEvent. The Permissions tab shows the exact running app path. It rechecks the system status every second while active, when opened, and when the app becomes active. Refresh checks it manually. The live check only reads permission status; it does not repeatedly request access or reload calendar contents. The app never treats a checked-looking stale entry as permission.

An event has the wrong date

Correct the dates in the editable popup before clicking Create event. Text without a recognized date suggests tomorrow at 09:00 with a one-hour duration; macOS date recognition can infer other times from explicit dates. After confirmation, use Calendar to edit the saved event.

Events appear more than once

Each selected calendar receives one copy. Pressing the shortcut again prepares a separate draft; confirming each draft creates another event. Review your destinations in Accounts and remove unwanted copies in Calendar.

Privacy and availability

Selected text is processed locally. MyEvent does not send it to an external AI service, add its own analytics or require an API key. Apple Translation processes text on-device; Apple may collect language-pair and API usage metrics, but not the source or translated content, as described in Apple's TranslationSession documentation. Event text and notes are saved to your selected calendars; those calendars may sync through their account providers.

If MyEvent needs to use Copy, it preserves the available clipboard formats and restores them after reading, unless it detects a concurrent clipboard change. Settings and the chosen language are stored locally. The bottom of Settings displays the version, build number and build date. A build increments its number every time, and a code change increments the patch version. A build refuses code changes unless this English guide has also been updated.

At the bottom right of every Settings tab, Quit exits MyEvent and disables its global shortcut. The highlighted Hide button at the far right hides the app while keeping it and the shortcut running. Click MyEvent in the Dock to show Settings again. These buttons stay in the same physical order in all languages. Hiding is not quitting or minimizing; the red close button still quits the app.

The ? button and Help menu open one reusable native macOS help window, not your browser. Reopening Help returns to this guide. Links remain inside that window. MyEvent has one settings window only; no empty system Settings scene is created. The app bundle declares its ICNS icon explicitly. Builds use Apple’s native iconutil encoder for every Finder/Dock icon size, including small list icons, and refresh Launch Services registration. This guide is bundled with the app and opens in a dedicated MyEvent macOS window without an internet connection. Links to external references require internet access. No online-hosted guide is configured: Sites publication is not enabled for this workspace. The guide is regenerated and bundled with every build; hosting remains a separate blocked step.

Requires macOS 14 or later. This build runs on the architecture of the Mac used to compile it. Distribution to other Macs requires appropriate signing and notarization.
